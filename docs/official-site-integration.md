# 公式サイトとの連携（役割分担と一体化）

> 2026-09-29 作成。公式サイト（minatocrew.com）と MINATO BRIDGE（event.minatocrew.com）が「2つのサイト」に見えないようにするための決めごとと、公式サイト側でやること。

## 役割分担

| | 公式サイト（minatocrew.com） | MINATO BRIDGE（event.minatocrew.com） |
|---|---|---|
| ひとことで | **MINATOを知る場所** | **イベントに参加する場所** |
| 載せるもの | MINATOとは・代表挨拶・イベントの考え方・サービス・よくある質問・ブログ・会社概要・規約・お問い合わせ | イベント一覧とイベントページ・申込・マイページ・クルーの申込・講座と動画 |
| 更新する人 | 公式サイトの担当（WordPress） | 運営スタッフ（管理画面） |
| 更新の頻度 | たまに（考え方・紹介が変わったとき） | 毎回（イベントごとに登録・申込を受ける） |

同じ内容を両方に書かない。イベントの情報（日時・料金・残席）は BRIDGE にだけ持ち、公式サイトには **埋め込み**（下の「公式サイト側でやること」）で出す。規約・プライバシーポリシーは公式サイトにだけ持ち、BRIDGE からはリンクする。

## 一体に見せるための決めごと

- **見た目**：参加者向けの画面は、公式サイトと同じオレンジの帯（`#dd9933`）・中央のロゴ（公式サイトの `logp3.png`）・右上のメニュー・オレンジのフッター（`#dd8b0f`）にする。中身は「海辺の午後」案の明るいデザイン
- **名前**：参加者に見える名前は公式サイトと同じ「MINATO」（タブの題名は「イベント一覧｜MINATO」）。「MINATO BRIDGE」は運営が使う管理画面の名前（船橋＝舵を取る場所）。参加者向けの名前は設定の「参加者向けの画面の名前」で変えられる
- **行き来**：BRIDGE のヘッダー左に「公式サイト」、右上のメニューに公式サイトの主なページ（設定の「メニューに並べる公式サイトのページ」）、フッターに規約類。イベントページの下に「MINATOってどんなコミュニティ？」と公式サイトの「MINATOとは」へのリンク
- **ドメイン**：`event.minatocrew.com`（公式サイトのサブドメイン）。アドレスでも同じサイトの一部に見える

## 公式サイト側でやること（WordPress）

管理画面の「設定」→「公式サイトとの連携」に、コピーできる形でまとめてある。

1. **ボタン・メニューのリンク先を変える**
   - ヘッダーの「イベント参加」（今は /registration/ の Googleフォーム）→ `https://event.minatocrew.com/?from=site`
   - ヘッダーの「クルー募集」（今は /crew/ の Contact Form 7）→ `https://event.minatocrew.com/crew?from=site`
   - メニューの「イベントスケジュール」（今は Googleカレンダー）→ `https://event.minatocrew.com/?from=site`、または下の埋め込みを貼る
   - `?from=site` を付けると、公式サイトから来た申込が「集計」で分かる
2. **イベント一覧を埋め込む**：WordPress のページに「カスタムHTML」ブロックを足して、次を貼る。イベントを登録・更新すると公式サイト側も自動で変わる

   ```html
   <div data-minato-events></div>
   <script src="https://event.minatocrew.com/assets/embed.js" async></script>
   ```

   - `data-limit="3"` で件数、`data-type="joshikai"` で形式を絞れる（トップページに近い3件、など）
   - 中身は iframe。高さは中身に合わせて自動で変わる。カードを押すと公式サイトのページごと BRIDGE のイベントページへ移る
   - 埋め込みを出せるのは、設定の「埋め込みを許すサイト」に入っているサイトだけ（既定は `https://minatocrew.com` と `https://www.minatocrew.com`）
3. **コードを貼れないとき**：WordPress の「RSS」ブロックに `https://event.minatocrew.com/feed.xml` を入れると、募集中のイベントが新着として並ぶ
4. **今の予約フォーム（Googleフォーム）・Googleカレンダー**は、BRIDGE で受付を始めたら公式サイトから外す（残すと申込が2か所に分かれる）

## 公式LINE との関係

今の運用では、参加者への案内は主に公式LINEで行っている（メールより LINE）。

- **いまできること（開発なし）**：公式LINEのリッチメニュー（トーク画面の下のボタン）とあいさつメッセージに、BRIDGE のリンクを入れる。イベント一覧 `/?from=line`・マイページ `/my`・クルー募集 `/crew?from=line`・講座 `/learn`。イベントごとのお知らせは「告知に使うリンクと文面」で LINE 用の文面を作って配信する
- **連携するとできること（要相談）**：LINE の Messaging API と LINE ログインを使うと、申込確認・リマインド・繰り上げなどをメールの代わりに LINE で自動で送る、マイページや講座を LINE でログインして開く、などができる。公式LINEのチャネルの設定（先方）と、送る通数に応じた料金プランの確認が要る

## こくちーず・SNS との関係

- こくちーずは「掲載（集客の窓口）」だけに使い、申込は BRIDGE のイベントページに集める
- イベントの画面の「告知に使うリンクと文面」で、こくちーず用・Instagram 用などのリンク入りの告知文を作ってコピーできる
- イベントページには SNS で共有したときの写真と説明（OGP）が付くので、LINE や Instagram のストーリーに貼っても見栄えがする

## 検索エンジン

- 本番（`.env` の `APP_ENV=production`）では、イベント一覧と募集中のイベントページだけ検索に載る（申込フォーム・マイページ・ログイン・管理画面は載せない）
- イベントページには Google 向けのイベント情報（schema.org の Event）を入れている。検索結果にイベントとして出やすくなる
- 本番前・検証中（`APP_ENV=local` など）は、すべての画面を検索に載せない
