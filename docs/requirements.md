## 1. 背景と目的

- 発端：林さんから「イベント主催者が使っているアプリ（岩手県人会アプリ）のように、MINATOのイベントも自動化できないか」という相談
- 目的：告知・申込・当日受付・会計・会のあとの手間を減らし、少人数で回せるようにする
- 参考：岩手県人会アプリ（飲み会専用の試作品。localhostで動作、未公開）

### 参考アプリから取り入れるもの
- 回の複製、定員到達での自動締切、キャンセル期限の自動計算
- 案内文の自動生成（募集／リマインド／締切／お礼）→ オープンチャットにコピペ
- 当日受付：名前を押すと到着と入金を同時に記録
- 会計の自動計算（集金 − 経費 − 主催分 = 収支）
- 会のあと：写真アルバム公開、領収書PDF

### 取り入れないもの
- 出身地の分布図、同郷マッチング
- 食べログからの店情報取得（壊れやすい・規約リスク）
- ブラウザ依存の本人判別

### 1-2. 追加の要望：申込と顧客の一元管理（2026-09-27）

- こくちーずやGoogleフォームなど、ばらばらの入口から来る申込を1か所に集めたい
- 顧客リスト（これまでの参加者）と各回の参加者を、まとめて管理したい
- 顧客リストは600件を超え、スプレッドシートでの管理が面倒になっている（今のスプレッドシートは後日受け取る）

これを受けた方針（案）：

- このアプリを **台帳** にする。申込の入口（こくちーず・Googleフォーム等）は今のまま使い、申込データをこちらに取り込む
- 人は **顧客** として1人1件にまとめ（名寄せ）、回ごとの申込・参加履歴をひもづける
- 取り込み方法（詳細は [data-intake.md](data-intake.md)）

| 入口 | 取り込み方法 |
|---|---|
| こくちーず | 主催者画面の「参加者名簿のダウンロード」CSV（Shift_JIS）を管理画面からアップロード。申込者を取れる公開APIは見当たらない |
| Googleフォーム | フォームに Apps Script を付け、送信のたびにこのアプリへ自動で送る。CSVアップロードも可 |
| Peatix（前払い） | 参加者リストのCSVをアップロード |
| LINE・口頭など | 管理画面で手入力 |
| 既存の顧客リスト | 最初に1回だけCSVで取り込む |

この方針で変わること：

- 定員での自動締切・キャンセル待ちは、申込を受ける側（こくちーず等）の機能に頼ることになる。このアプリでは人数の把握と定員超えの警告にとどまる
- 自前の申込フォームと個人専用URLは、入口を今のまま使うなら急ぎではなくなる
- 顧客リストとして個人情報が回をまたいで貯まる。持つ項目と利用目的を決める必要がある

### 用語

- **クルー**：MINATOのメンバー（月額5,500円）。オフラインイベントの参加費が3,000円引き、オンラインイベントは無料（公式サイトより）
- **わくMe**：価値観カード（WAKUME CARD、89枚）の名前（2026-09-28 Yumaさんより）。声掛けリストの「わくMe加入」や収支表の「わくME」の入金が何を指すか（カードを使った講座・認定など）は確認中

### 決定事項

- 2026-09-28：新しい申込フォームではメールアドレスを必須にする。予約確認メールの送り先・出禁チェックの照合・LINE以外での案内に使う。案内メールの受け取りは本人の同意制（特定電子メール法のため、同意日時と配信停止を記録）。案内メールを送る機能は次の段階で、最初の版はメールと同意を集め、条件で宛先リストを出すところまで
- 2026-09-28：「どこで知りましたか」の選択肢は、今のシートの集客媒体まで広げ、管理画面で追加できるようにする
- 2026-09-28：こくちーずは掲載だけで、申込はリンク先のMINATOのGoogleフォームで受けている。Peatixは使っていない。1-2 の表にある「こくちーず・PeatixのCSV取り込み」は不要
- 2026-09-28：今のスプレッドシートとフォーム（イベント予約・問い合わせ）は、アプリで刷新してよい（Yumaさんより）。今のシートとの同期は考えず、アプリを正のデータにして、最初に1回だけ移行する

### 1-3. 林さんからの方針（2026-09-27）

林さんが全体に共有した方針（原文の要約）：

- イベントアプリはYuma（酒井）が作る
- イメージは「こくちーずのような掲示板」。管理者と運用先はたくさん分散しておき、一本に集約して新規獲得の仕組みを作る
- 目的は新規集客、特に女子会の強化
- 女性のペルソナはあんじさんと相談して決める

こちらの読み取り（ヒアリングシートの「1. 認識の確認」「2. 新規集客・掲示板について」で確認中）：

- MINATOのイベントを一覧で公開し、そこから申し込める **自前の掲示板** を作る。1-2 で後回し候補にした「イベントページ＋申込フォーム」は最初の版の中心になる
- 集客の窓口（こくちーず、Instagram、LINEなど）や運営する人は複数のままでよく、申込と顧客の管理はこのアプリに集約する（1-2 の台帳の考え方はそのまま）
- 最初に作る形式は女子会
- どの窓口から新しい人が来たかを数えられるようにする（窓口ごとに掲示板へのリンクを分けるなど）
- 「管理者と運用先をたくさん分散」の意味は要確認。主催者ごとに管理画面を分ける（こくちーずのように複数の主催者が載せる）読み方もありうる
- 自前の掲示板だけでは人は来ないので、こくちーず等の集客力を手放すかどうかは慎重に決める

## 4. 構成

| 項目 | 内容 |
|---|---|
| サーバー | Xserver（sv16086。minatocrew.com と同じサーバーで、管理アカウントを借りて操作する。2026-09-28 更新） |
| 公式サイト | https://minatocrew.com/ |
| 公開URL | `event.minatocrew.com`（仮） |
| 言語 | PHP |
| データベース | MySQL（Xserver付属） |
| SSL | Xserver無料SSL |
| 申込の入口 | こくちーず・Googleフォーム等を継続利用し、申込データを取り込む（案） |
| 前払いの決済 | 既存サービス（Peatix等）を利用し、入金済みのみ記録 |
| LINE | 当面は案内文のコピペ運用 |

### 構成を選んだ理由
- 当日受付で複数人が同時に操作するため、スプレッドシートより本物のDBの方が安全
- MySQLは追加費用なし
- 運営が数字を見たい部分はCSV書き出しで補う

## 5. データ構造（案）

| テーブル | 主な項目 |
|---|---|
| event_types | 形式名、申込項目の定義、経費項目の定義、案内文テンプレート |
| events | 形式、回、日時、会場、定員（男女別可）、参加費、締切、キャンセル規定、状態 |
| customers | 顧客（1人1件）。名前、連絡先、運営メモ、個人専用トークン（持つ情報は最小限）※旧 participants |
| registrations | イベント、顧客、申込元（こくちーず等）と申込元での番号、追加項目の回答、支払い方法、状態（申込／キャンセル／キャンセル待ち） |
| checkins | 到着時刻、入金額、支払い方法、担当者 |
| expenses | イベント、項目、金額、メモ |
| inquiries | 参加者、内容、返信、対応状態 |
| admins | ログインID、パスワード（ハッシュ）、権限 |
| import_batches | 取り込み履歴（いつ・誰が・どのファイルを・何件） |

SQLにしたものは [`database/init/01_schema.sql`](../database/init/01_schema.sql)。

## 6. 運用ルール

- 個人情報は必要最小限だけ持つ
- 顧客リストで持つ項目と利用目的は林さんと決め、申込フォーム側にも利用目的を書いてもらう
- 管理画面のアカウントは個人ごとに発行（共有パスワードにしない）
- 収支表の構造は触らない。会計結果の書き出しで連携する
- 契約終了時はデータをCSVで引き渡す
