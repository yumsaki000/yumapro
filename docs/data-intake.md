# 申込の取り込みと顧客台帳（案）

> [requirements.md](requirements.md) の「1-2. 追加の要望：申込と顧客の一元管理」を形にするための設計メモ。
> こくちーずのCSVやGoogleフォームの実物を見るまでは案。

## 全体の流れ

```
こくちーず ──── CSV ─────────┐
Googleフォーム ─ 自動送信／CSV ─┤
Peatix ─────── CSV ─────────┼─→ 取り込み → 名寄せ（顧客） → 回ごとの申込 → 当日受付 → 会計 → CSV書き出し
LINE・口頭 ──── 手入力 ───────┘
```

申込を受ける場所（入口）は今のまま使い、このアプリは申込と顧客をまとめる台帳になる。

## 入口ごとの取り込み

### こくちーず

- 主催者の参加者管理ページにある「参加者名簿のダウンロード」でCSVを出す（文字コードは Shift_JIS）
- 管理画面で回を選んでアップロード → 列の対応を確認 → 取り込み
- 同じCSVを何度取り込んでも申込は重複させない。申込元での番号があればそれで、なければ「回 × 顧客」で同じ申込とみなし、キャンセルなどの変化は上書きする
- 列の並びはサンプルCSVを見てから決める
- 「出欠名簿のダウンロード」もある。当日受付をこくちーず側でもしているかは要確認
- 申込者を取れる公開APIは見当たらないので、CSVでの連携にする

### Googleフォーム

- **自動（おすすめ）**：フォームに Apps Script を付け、送信のたびに回答をこのアプリへ送る
  - 送り先：`https://event.minatocrew.com/hooks/google-form/{回のslug}`（仮）
  - 合言葉（`.env` に置く秘密の文字列）を付けて送り、合わないものは受け付けない
  - フォームの編集権限が必要
  - 定員に達したら、Apps Script でフォームの受付を止めることもできる
- **手動**：回答のスプレッドシートをCSVでダウンロードしてアップロード（UTF-8）

### Peatix

- 参加者リストのCSVをアップロード。前払いの入金済みとして記録する

### LINE・口頭

- 管理画面の回のページから手入力する

### 既存の顧客リスト

- 最初に1回だけCSVで取り込む。列の対応は実物を見てから

## 名寄せ（同じ人を1件にまとめる）

取り込むたびに、次の順で既存の顧客と照らし合わせる。

1. メールアドレスが一致 → 同じ顧客（大文字・小文字、前後の空白は無視）
2. 電話番号が一致 → 同じ顧客（ハイフンや空白を除いた数字で比べる）
3. 名前だけが一致 → 自動ではまとめない。「同じ人かも」の候補として出し、運営が手で統合する
4. どれにも当たらない → 新しい顧客として登録

- 名前は全角・半角と空白をそろえてから比べる
- 手で統合したときは、申込をまとめ先の顧客に付け替えて、もう一方は消す

## 取り込みの決まり

- 取り込んだ元データは `registrations.raw_data` にそのまま残す。列の対応を間違えても後で直せる
- CSVアップロード1回ごとに `import_batches` に記録し、いつ・誰が・何件入れたかを追えるようにする
- CSVの文字コードは自動で判定する（こくちーずは Shift_JIS、Googleのスプレッドシートは UTF-8）
- 取り込み前に「新規◯件・更新◯件・名寄せ候補◯件」を見せてから確定する

## この方式で変わること

- 定員での自動締切・キャンセル待ちは入口側の機能に頼る。このアプリでは人数の把握と定員超えの警告にとどめる（Googleフォームだけは上のとおり自動で止められる）
- 個人情報が回をまたいで貯まるので、持つ項目と利用目的を決め、申込フォーム側にも利用目的を書いてもらう
