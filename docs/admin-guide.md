# MINATO BRIDGE 管理画面の使い方

運営メンバー向けの手引き。スマホでも使える。URL は `https://event.minatocrew.com/admin`（本番公開後）。ローカルは `http://localhost:8080/admin`。

システムの名前は **MINATO BRIDGE**。船橋（ブリッジ）は船の舵を取る場所で、港（MINATO）のイベントの舵をここで取る、という意味。参加者向けの掲示板（`/`）も同じ名前で出る。

## 全体の流れ

1. イベントを作って「募集中」にする → 掲示板（`/`）に出る
2. イベントの詳細にある窓口別のリンク（`?from=instagram` など）を、公式LINE・Instagram・こくちーずなどに貼る
3. 参加者が申込フォームから申し込む → 自動で確認メール。定員に達していればキャンセル待ち
4. 前払いのイベントは、入金を確認したら管理画面で「入金確認済み」を付ける
5. 前日にリマインドメールが自動で届く。当日は「当日受付」で到着と入金を記録する
6. 翌日にお礼メール（アンケート付き）が自動で届く。イベントの詳細でアンケートの結果が見える
7. 会計で経費を入れて収支を出す。「集計」で窓口ごとの申込数と新規・リピートを見る

## ログイン

- アカウントは1人ずつ発行される（共有しない）。ログインIDとパスワードは発行した人（オーナー）から受け取る
- パスワードを5回続けて間違えると15分止まる。急ぐときはオーナーに「パスワードの再設定」を頼む（再設定すると止まっている状態も解除される）
- 8時間操作しないと自動でログアウトする

## トップ

- 「これからのイベント」に直近のイベントが出る。「当日受付」ボタンで受付画面に直接行ける
- 下のメニューから各機能へ

## イベント

こくちーずに載せる感覚で、上から順に埋めればイベントページができるようにしてある。入力は「1. 基本 → 2. 写真 → 3. 掲載する内容 → 4. 場所 → 5. 定員と参加費 → 6. 締切とキャンセル → 7. 公開」の順。保存ボタンは画面の下にいつも出ている。

- **前回のイベントをもとに作る（おすすめ）**：「新しいイベント」の一番上に、形式ごとの一番新しいイベントが出る。「これをもとに作る」で、説明・写真・料金などを写した下書きができる（第n回は +1）。日時と変わるところだけ直す。ほかのイベントをもとにするときはイベントの画面の「複製」
- **必須**はタイトル・開始日時・参加費だけ。形式を選ぶと、その形式の既定の支払い方法（前払い／当日払い）が入る
- **タイトル**：場所・中身・安心できること（例：「【渋谷】自分の可能性が広がる女子会｜価値観カードでワクワクトーク｜初参加・おひとり歓迎」）を入れると、こくちーずや検索で見つけてもらいやすい
- **写真**：表紙の1枚と、そのほかに8枚まで（まとめて選べる）。スマホの写真をそのまま選んでよい（横1600pxに縮めて保存）。並べた写真の「表紙にする」で表紙を入れ替えられる。表紙がないときは形式の色で埋まる
- **掲載する内容**（どれも任意。空欄の欄はページに出ない）：
  - 一言紹介：一覧のカード・イベントページの上・LINEなどで共有したときに出る（60〜120文字くらい）
  - 安心ポイント：1行に1つ。「初参加歓迎」「強引な勧誘は一切なし」などの候補をタップで足せる。イベントページとカードに札の形で出る
  - イベント内容：行の頭に「■」で見出し、「・」で箇条書き、`**ことば**` で太字。ボタンでも入れられる。URL はリンクになる
  - こんな方におすすめ（1行に1つ）、タイムスケジュール（「14:00 自己紹介」の形で1行に1つ）、持ち物・服装
  - よくある質問：ふだんは「設定」の共通のものが出る。このイベントだけ変えたいときに書く
  - 「ひな形を入れる」を押すと、空いている欄に書き方の見本が入る
- **場所**：「アクセス」（例：駒込駅 徒歩3分）と「地図に出す場所」（例：駒込駅）はページに出る。住所と道順のURLは申込んだ人にだけ見せる（確認メールと個人専用ページ）
- **定員**：空欄なら上限なし。男女別の定員・料金は「男女で分ける」を開いて、合コンなど必要なときだけ入れる
- **キャンセル期限**：前払いのイベントで空欄のまま作ると、開始の7日前が入る（今のキャンセルポリシーに合わせた既定）
- **状態**：下書き → 募集中 → 締切 → 終了。中止にもできる。「募集中」が掲示板に出る状態
- **保存してページを確認**：参加者に見える形で確かめられる（下書きのままでも見られる。申込ボタンは押せない）。イベントの画面の「ページを確認」からも見られる
- **告知に使うリンクと文面**：イベントの画面で、貼る場所（こくちーず・Instagram・LINE など）を選ぶと、その場所用のリンクと告知文（日時・場所・参加費・安心ポイント入り）ができる。コピーしてそのまま貼れる
- **形式の色**：掲示板のタグとカードの色は形式ごと（女子会＝ピンク、リトリート＝水色、自己啓発＝黄色、合コン＝淡いオレンジ）。形式を増やすときはテーブルの color で決める
- イベントの詳細では、申込者の一覧・入金・到着の状況が見える。「詳細」から参加費（クルー割引など）や入金確認を変えられる
- **申込者をCSVで**：イベントの詳細のボタンで、申込者の一覧（名前・連絡先・状態・入金・到着・知った経路・紹介者・申込フォームの回答）を CSV で書き出せる。受付表の印刷や、ほかの表計算に使う

## 次回のお知らせ（使うときだけ）

こくちーずの「興味ありリスト」にあたる。形式（女子会・リトリートなど）ごとに登録してもらい、その形式のイベントの募集を始めたらメールで知らせる。

- 使うときは「設定 → 使う機能 →「次回のお知らせ」の登録を出す」にチェック。イベント一覧とイベントページの下に登録欄が出る（オフのときは何も出ない）
- 登録するとまず確認メールが届き、リンクを開いた人だけに届く（受け取りの同意の記録。いたずらで他人を登録できない）
- 送るのは運営：イベントを「募集中」にしたら、イベントの詳細の「次回のお知らせ」→「お知らせを送る」。その形式の登録者全員に届く。1つのイベントにつき1回だけ（二重に押しても送らない）
- メールのリンクから来た申込は、集計の窓口に「次回のお知らせメール」と出る
- 本人はメールのリンクから、形式の変更・受け取りの停止・再開ができる
- 登録者の一覧はイベントの詳細の「登録者の一覧」（`/admin/follows`）。文面は「設定 → 次回のお知らせと友だち招待」
- 顧客台帳とは別に持つ（申込したことのない人も登録できる。メールアドレスだけ）

## 無断キャンセル

連絡なしで来なかった人を記録しておき、次に申し込んだときに気づけるようにする。

- 当日受付を使ったイベントでは、開催後にイベントの詳細の申込者一覧の上に「到着の記録がない N人を無断キャンセルにする」が出る。押すとまとめて印が付く（連絡があった人は「外す」で戻す）
- 1人ずつ付けるときは、開催後の申込者一覧の「到着」の欄の「無断キャンセル」
- 印が付いた人は、申込者一覧・顧客の詳細・申込の詳細に「無断キャンセルN回」と出る
- 「設定 → 使う機能 → 無断キャンセルが何回の人を知らせるか」（既定2回）以上の人が申し込むと、運営への通知メールが届く（件名【無断キャンセルN回】）。申込はそのまま受け付ける。0 にすると知らせない
- 本人には見えない（運営の記録だけ）

## 掲示板と申込フォーム（参加者が使う画面）

- 掲示板（`/`）には「募集中」と「締切」のイベントが出る。「下書き」「終了」「中止」は出ない。形式で絞り込める
- イベントページは、写真 → 一言紹介 → 安心ポイント → 日時・場所・参加費・持ち物 → イベント内容 → こんな方におすすめ → タイムスケジュール → よくある質問 → アクセス（地図）→ キャンセルについて → MINATOってどんなコミュニティ？ → シェア、の順（こくちーずの掲載ページと同じ流れ）。右（スマホでは画面の下）に参加費・残席・申込ボタン
- 日時の横の「カレンダーに追加」で、参加者が自分のカレンダー（Google・iPhone）に入れられる。シェアは LINE・X・Facebook・リンクのコピー
- 会場の住所は出さず、申込が確定した人の確認メールと個人専用ページにだけ出す
- 申込フォームの項目：名前・フリガナ・メール（必須）・電話（必須）・性別（男女別の定員か料金があるイベントでは必須）・SNS・どこで知ったか・紹介者・意気込み・質問、形式ごとの追加項目、同意（注意事項・お支払い・キャンセルポリシー）、案内メールの同意（任意）
- 同意文と説明文は「設定」で変えられる
- 申込が入ると自動で：
  - **名寄せ**：電話番号 → メールの順で既存の顧客を探し、いれば同じ顧客に、いなければ新しい顧客にする（空いている項目だけ埋める）
  - **出禁チェック**：連絡先が出禁の人と一致すれば「出禁該当」としてキャンセル待ちに止める（本人には普通のキャンセル待ちの案内が届く）。名前だけ一致なら「要確認」の印を付けて申込にする。どちらもイベントの詳細に赤・黄の印が出るので、運営が確かめる
  - **定員**：定員に達していればキャンセル待ちにする
  - **確認メール**：申込なら会場の住所と振込先（前払いのイベント）入り、キャンセル待ちならその旨
- 同じ人が同じイベントに二度申し込むと、新しく作らず確認メールをもう一度送る

## 個人専用ページ

- 確認メールの「お申込み内容の確認」のURLから開く（顧客ごとのURL。他の人には教えないよう案内している）
- 本人ができること：申込内容と会場・振込先の確認、キャンセル（開催前でキャンセル期限内。キャンセル待ちはいつでも）、案内メールの受け取りの切り替え、参加したイベントのアンケート
- 本人がキャンセルすると、キャンセル待ちの先頭の人が自動で繰り上がり、繰り上げのメールが届く。管理画面でキャンセルしたときも同じ

## 自動メール

- 申込確認・キャンセル待ち・繰り上げ・キャンセル確認は、その場で自動で送る
- 前日のリマインドと翌日のお礼（アンケートのリンク付き）は、サーバーの定期実行（毎時）で自動で送る。イベントの詳細の「今すぐ送る」で手でも送れる。同じ人に同じメールは二度送らない
- お礼メールは、当日受付を使ったイベントでは到着した人だけに、使っていないイベントでは申込の人全員に送る
- メールアドレスのない顧客（手入力・移行の人）には送れない。イベントの詳細で申込者のメールの有無を確かめる
- 文面は「設定」で変えられる。`{name}` `{event_title}` `{my_url}` などがその申込の内容に置き換わる

## 申込の手入力

スタッフの声かけ（LINE・口頭）で決まった人を登録する。イベントの詳細 → 「申込を追加」。

1. 名前・フリガナ・電話番号で顧客を探す。いれば「この人を申し込む」
2. いなければ「新しい顧客として登録して申し込む」。電話・メール・名前が既存の顧客と同じときは警告が出るので、同じ人ならその人を選び直す
3. 参加費（既定はイベントの参加費。男女別料金があれば性別で変わる）、どこで知ったか、メモを入れて「申込を追加する」
4. 定員に達していると自動で**キャンセル待ち**になる。定員を超えて入れるときは「定員を超えて申込にする」にチェック
5. **出禁**の人は警告が出る。それでも入れるときはチェックを入れる

- 前払いのイベントでは、入金を確認したら「入金を確認済み」を付ける（申込時か、申込の詳細から）
- キャンセルは申込者一覧の「キャンセル」。戻すときは「申込に戻す」（定員内なら申込、いっぱいならキャンセル待ちのまま）
- キャンセル待ちの人を入れるときは「繰り上げ」

## 当日受付

イベントの詳細 → 「当日受付」（トップの「これからのイベント」からも行ける）。

- 来た人の「到着」を押す。当日払いの人は金額（既定は参加費）と支払い方法を確かめてから押す。前払い済みの人は金額欄が出ない
- 押し間違えたら「取り消し」
- 人が多いときは名前で絞り込む
- 申込にない人が来たら「飛び入りの人を追加」
- キャンセル待ちの人が来て「到着」を押すと、そのまま申込（参加）になる
- 2人で同時に受付をしても、同じ人が二重に記録されることはない

## 顧客台帳

- 名前・フリガナ・電話番号・メール・SNSで検索できる。数字だけ入れると電話番号、@ があるとメールで探す
- 顧客の詳細で、連絡先・参加履歴・運営メモ・移行元のデータ（今のスプレッドシートの行）が見える
- **案内メールの同意**：本人が同意したときだけチェックを入れる。同意した日時と、外した日時を記録する（法律上必要）
- **出禁**：詳細の下の「出禁にする」。理由は運営向けのメモ。出禁の人は一覧・受付・申込で赤い印が出る。解除もできる
- **名寄せ**：顧客台帳の「名寄せ」に、同じ電話番号・同じメール・同じ名前の組が出る。「残す顧客」を選んで「まとめる」と、ほかの人の申込が残す人に付け替えられ、ほかの人は消える。同姓同名の別人もいるので、フリガナ・電話・参加履歴を見て判断する。同じイベントに両方の申込がある組はまとめられない（先にどちらかをキャンセルする）
- 顧客の詳細にも「同じ人かもしれない顧客」が出るので、そこからもまとめられる
- **CSVで書き出す**（オーナーだけ）：顧客台帳の全員を CSV で書き出せる（連絡先・申込と参加の数・無断キャンセルの数・最後のイベント・出禁など）。全員の連絡先が入るので、書き出したファイルは運営の中だけで扱い、使い終わったら消す。人に送らない
- 顧客の詳細の「紹介した人」に、その人の招待リンクから申し込んだ人が出る

## 友だち招待（使うときだけ）

- 使うときは「設定 → 使う機能 → 友だち招待のリンクを出す」にチェック。参加者のマイページに、その人専用の招待リンクと「LINEで送る」ボタンが出る。申込中のイベントには「このイベントに友だちを誘う」も出る
- リンクから来た人が申し込むと、申込に紹介者が記録される（自分のリンクから自分で申し込んだときは記録しない）。フォームの「どこで知りましたか」は最初から「友人・知人の紹介」になる
- 紹介者は申込者一覧・申込の詳細・顧客の詳細に出る。「集計」に紹介の多い人の上位が出る（お礼や特典を考えるときに）
- 出禁の人のマイページには出さない

## 出禁リスト

- トップのメニューか顧客台帳の「出禁リスト」から。出禁の人の一覧（名前・連絡先・理由・登録した人と日時）と検索
- **登録**：「出禁に登録」で顧客台帳から探して選ぶ。台帳にいない人は、その場で分かる項目だけ入れて登録できる。理由は短く、経緯・メモには「いつ・どのイベントで・何があったか」を書く。証拠の画像はアプリに貼らず、保管場所だけ書く
- **申込フォームでの判定**（今のスクリプトと同じルール）
  - 電話・メール・SNSのどれかが出禁の人と一致 → 「出禁該当」。申込はキャンセル待ちに止まり、本人には普通のキャンセル待ちの案内だけ届く
  - 名前（空白を除いて3文字以上）だけ一致 → 「要確認」。申込は通常どおり進む
  - どちらも、イベントの詳細の申込者一覧に印が付き、トップと出禁リストに「確認待ち」として出る
- **確認待ちの処理**：申込の詳細を開くと、今回の申込と出禁リストの人を並べて見比べられる。「別人だった」で印を消す。「同じ人だった」でその顧客を出禁にし、申込をキャンセルにする（キャンセル待ちの人がいれば自動で繰り上がる）。本人への連絡は運営から行う
- **運営への通知メール**：「設定 → 運営への通知メールの宛先」を入れると、出禁該当・要確認の申込があったときにメールが届く（申込の詳細へのリンク付き）。「すべての申込を通知する」に 1 を入れると、すべての申込を知らせる
- **解除**：出禁リストか顧客の詳細から。解除すると理由・経緯も消える
- 手入力のときは、出禁の人を選ぶと警告が出る。チェックを入れないと登録できない
- 今のスプレッドシートの出禁リストは、公開前に1回だけ移す（[migration.md](migration.md)）

## クルー（月額のメンバー）

- 顧客ごとに「クルーの状態」（未加入／申込中／加入中／脱退）と加入日・脱退日を持つ。顧客の詳細の「クルー」で変えられる
- **クルー料金**：イベントの設定に「クルー料金」を入れると、加入中のクルーが申し込んだとき（フォームでも手入力でも）自動でその料金になる
- **募集ページ**（`/crew`）：説明・特典・月額の文言・規約へのリンクは「設定」で変えられる。申込があると、本人に確認メール、運営に通知メールが届く
- **申込の承認**：「クルー」画面の上に申込が並ぶ。「承認してクルーにする」で加入中になり、本人に加入のご案内メールが届く。月額の支払い方法は運営からご案内する（アプリでは受け取らない）
- 今のシートの「クルー加入日・脱退日」は、顧客の移行のときに一緒に移る

## 講座・動画（クルー専用・有料コンテンツ）

- 「講座」画面で講座を作る。最初に **この講座を見られる人** を「全員に公開／クルー専用／有料」から選ぶ。有料を選んだときだけ料金の欄が出て、「クルーは買わずに見られる（クルーの特典にする）」も選べる
- 講座の画面の「講座の回を追加」で、回のタイトル・YouTube の動画の URL・**動画の下に出す説明**（■見出し・「・」箇条書き・太字・URLのリンクが使える）を入れる。URL を貼るとその場でサムネイルが出るので、違う動画を貼っていないか確かめられる。文章だけの回も作れる
- 動画は YouTube 側で**限定公開**にする（リンクを知っている人だけ見られる設定。アプリのページからだけ案内する）
- 各回の「このイベントを見られる人」で **お試し（無料公開）** を選ぶと、そのイベントだけ誰でも見られる（第1回だけお試しにして、続きはクルー専用、という出し方）。最初の回は、はじめからお試しが選ばれている
- 講座の回の順番は上下のボタンで入れ替える。回ごとに「下書き」にして隠せる
- 参加者向けの「講座・動画」は、最初の動画のサムネイル付きのカードで並ぶ（見られる人・料金・お試しの回数が出る）
- **参加者のログイン**：クルー限定や購入した講座を見るには、参加者がログインする。メールアドレスを入れるとログイン用のリンクが届く方式（パスワードなし。30分・1回だけ有効）。確認メールの個人専用URLを開いたときもログイン状態になる
- **購入の流れ**：参加者が「購入する」を押す → 振込先のメールが届き、運営にも通知 → 「講座 → 購入の管理」で入金を確認して「入金確認済みにする」→ 本人に視聴のご案内メールが届き、見られるようになる
- 公開ページに出るのは「公開」の講座だけ。「下書き」にすると隠れる（購入した人がいる講座は消せない）

## 会計（確定申告に使える形）

「会計」は年ごと（右上で年を選ぶ）。その年の売上・経費・主催分・差し引き、**月ごと**の表、**勘定科目ごとの経費**、イベントごとの収支、イベントに付かない経費が1画面で見える。

- **収入** ＝ 前払いで入金確認済みの参加費 ＋ 当日受付で記録した入金（講座の購入は入金確認済みのもの）
- **収支** ＝ 収入 − 経費 − 主催分
- **経費の入れ方**：イベントの経費はイベントの会計（イベントの詳細 →「会計」）で、サーバー代・広告費・振込手数料のようにどのイベントのものとも言えない経費は「会計」の一番下の「イベントに付かない経費」で入れる。項目・金額のほかに次を入れておくと、確定申告のときに困らない
  - **勘定科目**：仕入高・賃借料・外注費・旅費交通費・広告宣伝費・消耗品費・通信費・会議費・接待交際費・支払手数料・雑費から選ぶ（それぞれの目安が選択肢に出る）。選ばないと項目の名前から自動で当てる（「交通費」→旅費交通費、「店への支払い」→仕入高、など）
  - **支払った日**：空ならイベントの日にする（イベントに付かない経費は必須）
  - **支払先**：店・会場・講師の名前など
  - **領収書・レシートを保管している**：印がない経費があると「会計」に件数が出る。確定申告の前に手元にあるか確かめる
  - あとから直すときは経費の「直す」
- **確定申告の書き出し**（「会計」の上のボタン。その年の分を CSV で。Excel・Googleスプレッドシート・会計ソフトで開ける）
  - **年間のまとめ**：売上・経費・主催分・差し引きの合計、勘定科目ごとの経費、月ごとの表
  - **売上の明細**：日付・区分（前払い／当日／講座）・イベント・名前・受け取り方法・入金日・金額
  - **経費の明細**：日付・勘定科目・項目・支払先・イベント・金額・領収書の有無・メモ（主催分も「要確認」として並ぶ）
  - **イベントごとの収支**
- **日付の決め方**：参加費はイベントの日の売上（前払いで先に受け取っていても）。講座は入金を確認した日。経費は支払った日。中止のイベントの参加費は入れない（返金する前提）。画面の「数え方」にも書いてある
- **主催分**：経費になるかは中身しだい（外の人への支払いなら外注費など、運営の取り分なら経費ではない）。書き出しでは「要確認」として分けてある。ヒアリング 5-4 で中身を確かめる
- **年の区切り**：個人の確定申告は1月〜12月（既定）。4月始まりなどにするときは「設定 → 会計 → 会計年度の始まりの月」
- 勘定科目の最終的な区分は、税理士さんか会計ソフトで確かめる。領収書・レシートの現物（または写真）はアプリとは別に7年間保管する
- まだ記録していないもの：クルーの会費（月額）。記録するようになったら売上に足す

## 集計

- 月ごととイベントごとに、申込数・新規／リピート・女性の数と割合、窓口別（リンクの `?from=`）・知った経路別（本人の回答）・申込元別（フォーム／手入力／移行）の数が出る
- 「新規」はそのイベントより前に申込がない人。効果測定（要件の10）はここの数字で見る
- 友だち招待を使っているときは、紹介の多い人の上位も出る

## 設定

- 掲示板の見出し（「港は、旅立つ場所であり帰ってくる場所。」）と一言、説明文、イベントの詳細の「よくある質問」（Q. と A. の行で書く）、イベントページの「主催について」、問い合わせ先、公式LINEのURL、申込フォームの同意文、振込先、メールの差出人と文面を変えられる。空欄にすると既定の文に戻る
- **公式サイトとのつながり**：参加者向けの画面の名前（既定は「MINATO」）、公式サイトのURL、右上のメニューに並べる公式サイトのページ（「名前 | URL」を1行に1つ）、フッターのリンク、埋め込みを許すサイト
- **公式サイトとの連携**（設定の上のリンク、またはトップから）：公式サイトのボタンのリンク先、イベント一覧の埋め込みコード、RSS の URL をコピーできる。くわしくは [official-site-integration.md](official-site-integration.md)
- **振込先はここにだけ書く**（リポジトリや資料には書かない）
- **使う機能**：「次回のお知らせ」の登録欄、友だち招待のリンク、無断キャンセルを何回から知らせるか。使わないものはチェックを外しておけば画面に出ない（準備だけしてある）
- **会計**：会計年度の始まりの月（既定は1月）
- 「どこで知りましたか」の選択肢は「設定」の中のリンクから。使わなくなったものは「表示」を外す（過去の記録は残る）。順の数字が小さいほど上に出る

## 運営メンバー（オーナーだけ）

- メンバーの追加、表示名・権限・有効／無効の変更、パスワードの再設定
- パスワードを空のまま追加・再設定すると自動で作られ、次の画面に1回だけ表示される。本人に安全な方法で伝える
- 自分の権限は自分では変えられない。辞めた人は「無効」にする（消さない。記録に名前が残る）
- 全員ログインできなくなったときは、サーバーで `php bin/create-admin.php --reset` を実行してパスワードを再設定する

## 困ったとき

- 「送信できませんでした」と出たら、画面を開いてから時間がたっている。前の画面に戻って読み込み直す
- 「権限がありません」はオーナーだけができる操作
- 画面がおかしい・エラーが出るときは、開発者（Yuma）に画面の写真を送る
