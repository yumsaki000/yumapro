# MINATO BRIDGE 管理画面の使い方

運営メンバー向けの手引き。スマホでも使える。URL は `https://event.minatocrew.com/admin`（本番公開後）。ローカルは `http://localhost:8080/admin`。

システムの名前は **MINATO BRIDGE**。船橋（ブリッジ）は船の舵を取る場所で、港（MINATO）のイベントの舵をここで取る、という意味。参加者向けの掲示板（`/`）も同じ名前で出る。

## 全体の流れ

1. 回を作って「募集中」にする → 掲示板（`/`）に出る
2. 回の詳細にある窓口別のリンク（`?from=instagram` など）を、公式LINE・Instagram・こくちーずなどに貼る
3. 参加者が申込フォームから申し込む → 自動で確認メール。定員に達していればキャンセル待ち
4. 前払いの回は、入金を確認したら管理画面で「入金確認済み」を付ける
5. 前日にリマインドメールが自動で届く。当日は「当日受付」で到着と入金を記録する
6. 翌日にお礼メール（アンケート付き）が自動で届く。回の詳細でアンケートの結果が見える
7. 会計で経費を入れて収支を出す。「集計」で窓口ごとの申込数と新規・リピートを見る

## ログイン

- アカウントは1人ずつ発行される（共有しない）。ログインIDとパスワードは発行した人（オーナー）から受け取る
- パスワードを5回続けて間違えると15分止まる。急ぐときはオーナーに「パスワードの再設定」を頼む（再設定すると止まっている状態も解除される）
- 8時間操作しないと自動でログアウトする

## トップ

- 「これからの回」に直近の回が出る。「当日受付」ボタンで受付画面に直接行ける
- 下のメニューから各機能へ

## 回（イベントの各回）

- **新しい回**：形式（リトリート／女子会／自己啓発／合コン）を選ぶと、その形式の既定の支払い方法（前払い／当日払い）が入る。タイトル・開始日時・参加費は必須
- **定員**：空欄なら上限なし。男女別の定員・料金は合コンなど必要なときだけ入れる
- **キャンセル期限**：前払いの回で空欄のまま作ると、開始の7日前が入る（今のキャンセルポリシーに合わせた既定）
- **状態**：下書き → 募集中 → 締切 → 終了。中止にもできる。「募集中」が掲示板に出る状態（掲示板は準備中）
- **複製**：回の詳細の「複製」を押すと、同じ内容の下書きができる。第n回は +1 され、日時はそのままなので直して保存する
- 回の詳細では、申込者の一覧・入金・到着の状況が見える。「詳細」から参加費（クルー割引など）や入金確認を変えられる

## 掲示板と申込フォーム（参加者が使う画面）

- 掲示板（`/`）には「募集中」と「締切」の回が出る。「下書き」「終了」「中止」は出ない
- 回の詳細には残りの席数が出る。会場の住所は出さず、申込が確定した人の確認メールと個人専用ページにだけ出す
- 申込フォームの項目：名前・フリガナ・メール（必須）・電話（必須）・性別（男女別の定員か料金がある回では必須）・SNS・どこで知ったか・紹介者・意気込み・質問、形式ごとの追加項目、同意（注意事項・お支払い・キャンセルポリシー）、案内メールの同意（任意）
- 同意文と説明文は「設定」で変えられる
- 申込が入ると自動で：
  - **名寄せ**：電話番号 → メールの順で既存の顧客を探し、いれば同じ顧客に、いなければ新しい顧客にする（空いている項目だけ埋める）
  - **出禁チェック**：連絡先が出禁の人と一致すれば「出禁該当」としてキャンセル待ちに止める（本人には普通のキャンセル待ちの案内が届く）。名前だけ一致なら「要確認」の印を付けて申込にする。どちらも回の詳細に赤・黄の印が出るので、運営が確かめる
  - **定員**：定員に達していればキャンセル待ちにする
  - **確認メール**：申込なら会場の住所と振込先（前払いの回）入り、キャンセル待ちならその旨
- 同じ人が同じ回に二度申し込むと、新しく作らず確認メールをもう一度送る

## 個人専用ページ

- 確認メールの「お申込み内容の確認」のURLから開く（顧客ごとのURL。他の人には教えないよう案内している）
- 本人ができること：申込内容と会場・振込先の確認、キャンセル（開催前でキャンセル期限内。キャンセル待ちはいつでも）、案内メールの受け取りの切り替え、参加した回のアンケート
- 本人がキャンセルすると、キャンセル待ちの先頭の人が自動で繰り上がり、繰り上げのメールが届く。管理画面でキャンセルしたときも同じ

## 自動メール

- 申込確認・キャンセル待ち・繰り上げ・キャンセル確認は、その場で自動で送る
- 前日のリマインドと翌日のお礼（アンケートのリンク付き）は、サーバーの定期実行（毎時）で自動で送る。回の詳細の「今すぐ送る」で手でも送れる。同じ人に同じメールは二度送らない
- お礼メールは、当日受付を使った回では到着した人だけに、使っていない回では申込の人全員に送る
- メールアドレスのない顧客（手入力・移行の人）には送れない。回の詳細で申込者のメールの有無を確かめる
- 文面は「設定」で変えられる。`{name}` `{event_title}` `{my_url}` などがその申込の内容に置き換わる

## 申込の手入力

スタッフの声かけ（LINE・口頭）で決まった人を登録する。回の詳細 → 「申込を追加」。

1. 名前・フリガナ・電話番号で顧客を探す。いれば「この人を申し込む」
2. いなければ「新しい顧客として登録して申し込む」。電話・メール・名前が既存の顧客と同じときは警告が出るので、同じ人ならその人を選び直す
3. 参加費（既定は回の参加費。男女別料金があれば性別で変わる）、どこで知ったか、メモを入れて「申込を追加する」
4. 定員に達していると自動で**キャンセル待ち**になる。定員を超えて入れるときは「定員を超えて申込にする」にチェック
5. **出禁**の人は警告が出る。それでも入れるときはチェックを入れる

- 前払いの回では、入金を確認したら「入金を確認済み」を付ける（申込時か、申込の詳細から）
- キャンセルは申込者一覧の「キャンセル」。戻すときは「申込に戻す」（定員内なら申込、いっぱいならキャンセル待ちのまま）
- キャンセル待ちの人を入れるときは「繰り上げ」

## 当日受付

回の詳細 → 「当日受付」（トップの「これからの回」からも行ける）。

- 来た人の「到着」を押す。当日払いの人は金額（既定は参加費）と支払い方法を確かめてから押す。前払い済みの人は金額欄が出ない
- 押し間違えたら「取り消し」
- 人が多いときは名前で絞り込む
- 申込にない人が来たら「飛び入りの人を追加」
- キャンセル待ちの人が来て「到着」を押すと、そのまま申込（参加）になる
- 2人で同時に受付をしても、同じ人が二重に記録されることはない

## 顧客台帳

- 名前・フリガナ・電話番号・メール・SNSで検索できる。数字だけ入れると電話番号、@ があるとメールで探す
- 顧客の詳細で、連絡先・参加履歴・運営メモ・移行元のデータ（今のスプレッドシートの行）が見える
- **案内メールの同意**：本人が同意したときだけチェックを入れる。同意した日時と、外した日時を記録する（法律上必要）
- **出禁**：詳細の下の「出禁にする」。理由は運営向けのメモ。出禁の人は一覧・受付・申込で赤い印が出る。解除もできる
- **名寄せ**：顧客台帳の「名寄せ」に、同じ電話番号・同じメール・同じ名前の組が出る。「残す顧客」を選んで「まとめる」と、ほかの人の申込が残す人に付け替えられ、ほかの人は消える。同姓同名の別人もいるので、フリガナ・電話・参加履歴を見て判断する。同じ回に両方の申込がある組はまとめられない（先にどちらかをキャンセルする）
- 顧客の詳細にも「同じ人かもしれない顧客」が出るので、そこからもまとめられる

## 出禁リスト

- トップのメニューか顧客台帳の「出禁リスト」から。出禁の人の一覧（名前・連絡先・理由・登録した人と日時）と検索
- **登録**：「出禁に登録」で顧客台帳から探して選ぶ。台帳にいない人は、その場で分かる項目だけ入れて登録できる。理由は短く、経緯・メモには「いつ・どの回で・何があったか」を書く。証拠の画像はアプリに貼らず、保管場所だけ書く
- **申込フォームでの判定**（今のスクリプトと同じルール）
  - 電話・メール・SNSのどれかが出禁の人と一致 → 「出禁該当」。申込はキャンセル待ちに止まり、本人には普通のキャンセル待ちの案内だけ届く
  - 名前（空白を除いて3文字以上）だけ一致 → 「要確認」。申込は通常どおり進む
  - どちらも、回の詳細の申込者一覧に印が付き、トップと出禁リストに「確認待ち」として出る
- **確認待ちの処理**：申込の詳細を開くと、今回の申込と出禁リストの人を並べて見比べられる。「別人だった」で印を消す。「同じ人だった」でその顧客を出禁にし、申込をキャンセルにする（キャンセル待ちの人がいれば自動で繰り上がる）。本人への連絡は運営から行う
- **運営への通知メール**：「設定 → 運営への通知メールの宛先」を入れると、出禁該当・要確認の申込があったときにメールが届く（申込の詳細へのリンク付き）。「すべての申込を通知する」に 1 を入れると、すべての申込を知らせる
- **解除**：出禁リストか顧客の詳細から。解除すると理由・経緯も消える
- 手入力のときは、出禁の人を選ぶと警告が出る。チェックを入れないと登録できない
- 今のスプレッドシートの出禁リストは、公開前に1回だけ移す（[migration.md](migration.md)）

## 会計

- 「会計」に回ごとの収入・経費・主催分・収支の一覧が出る
- **収入** ＝ 前払いで入金確認済みの参加費 ＋ 当日受付で記録した入金
- **収支** ＝ 収入 − 経費 − 主催分
- 回の会計で経費を項目ごとに入れる（項目は形式ごとの候補から選べるし、自由に書ける）。主催分もここで変えられる
- 収支表への書き出しは次の段階

## 集計

- 月ごとと回ごとに、申込数・新規／リピート・女性の数と割合、窓口別（リンクの `?from=`）・知った経路別（本人の回答）・申込元別（フォーム／手入力／移行）の数が出る
- 「新規」はその回より前に申込がない人。効果測定（要件の10）はここの数字で見る

## 設定

- 掲示板の説明文・問い合わせ先・公式LINEのURL、申込フォームの同意文、振込先、メールの差出人と文面を変えられる。空欄にすると既定の文に戻る
- **振込先はここにだけ書く**（リポジトリや資料には書かない）
- 「どこで知りましたか」の選択肢は「設定」の中のリンクから。使わなくなったものは「表示」を外す（過去の記録は残る）。順の数字が小さいほど上に出る

## 運営メンバー（オーナーだけ）

- メンバーの追加、表示名・権限・有効／無効の変更、パスワードの再設定
- パスワードを空のまま追加・再設定すると自動で作られ、次の画面に1回だけ表示される。本人に安全な方法で伝える
- 自分の権限は自分では変えられない。辞めた人は「無効」にする（消さない。記録に名前が残る）
- 全員ログインできなくなったときは、サーバーで `php bin/create-admin.php --reset` を実行してパスワードを再設定する

## 困ったとき

- 「送信できませんでした」と出たら、画面を開いてから時間がたっている。前の画面に戻って読み込み直す
- 「権限がありません」はオーナーだけができる操作
- 画面がおかしい・エラーが出るときは、開発者（Yuma）に画面の写真を送る
